## 오류 이름: AttributeError: 'numpy.ndarray' object has no attribute 'replace'
* **발생한 이유:** pandas DataFrame에서 딕셔너리 내부의 값을 가져오거나 parquet 파일의 특정 필드 값을 가져올 때, 해당 값이 `numpy.ndarray` 형태 저장되어 있을 수 있습니다. 이때 문자열(string) 전용 메소드인 `.replace()`를 바로 호출하면 에러가 발생합니다.
* **바로잡은 사항:** `.replace()` 등 문자열 메소드를 사용하기 전에 `isinstance(val, str)`로 타입을 , `numpy.ndarray`를 리스트로 변환한 후 json 직렬화하여 체 문자열로 안전한 변환 함수(`safe_str`)를 적용하여 해결했습니다.
* **앞으로 유의:** 데이터프레임이나 JSON/Parquet에서 값을 추출한 직후 문자열 조작을 하려    항상 변수가 정확히 문자열(`str`) 타입인지 확인해야 합니다.

## 오류 이름: Extractive Match Regex 충돌 (정답 부풀려짐 오류)
* **발생한 이유:** `ai2d_gen` 등 객관식 태스크에서 프롬프트에 `Respond with... (e.g. "Answer: A")`를 지시하여 모델이 `Answer: B`처럼 출력하게 유도했습니다. 하지만 평가 프레임워크의 단순 출력 추출 로직이 문자열 `Answer: B`에서 단어 `Answer`의 `A`와 알파벳 `B`를 모두 추출해버립니다. 따라서 실제 정답이 `A`일 경우, 모델이 `B`를 골란음에도 불구하고 `A`가 추출 목록에 존재하여 정답(1.0)으로 처리되는 심각한 오류가 발생했습니다.
* **바로잡은 사항:** 현상 원인을 파악하였으며, 앞으로 프롬프트 설계 시 평가 메트릭의 정규식 추출 로직과 춙돌하는 단어(예: Answer, B... 등 선택지를 포함하는 영단어)를 피하도록 `정답: `과 같은 한글 접두어를 쓰거나 메트릭의 정규식을 더 엄격하게 수정해야 합니다.
* **앞으로 유의할점:** LLM 벤치마크 평가 시, 모델에게 요구하는 출력 포맷(Output Format)이 메트릭의 정규표현식(Regex)이나 Rule-based 추출 방식과 간섭을 일으키지 않는지 반드시 교차 검증해야 합니다.

## 오류 이름: LightEval VLM `--vision-model` 에러 및 평가 캐시(Cache) 착각
* **발생한 이유:** Qwen-VL(Qwen3.5-9B)과 같은 비전-언어 모델(VLM)을 텍스트 전용 데이터셋(KMMLU 등)에서 평가할 때, 모델의 아키텍처를 로드하려면 무조건 `--vision-model` 옵션이 필요할 것이라고 섣불리 착각했습니다. 하지만 실제로는 `lighteval` 프레임워크 특성상 `--vision-model` 옵션을 주면 "모든 프롬프트에 반드시 이미지가 있어야 한다"고 판단하여 텍스트 데이터셋에서 `ValueError: Multimodal prompts require images...` 에러를 뿜고 강제 종료됩니다. 
또한, 옵션을 정상적으로 빼고 `--max-samples 100`으로 돌렸음에도 불구하고 평가가 실행되지 않는 현상이 있었는데, 이는 에러 때문이 아니라 과거에 `--max-samples 3`으로 돌려둔 Parquet 결과 파일이 남아 있어서 프레임워크가 이를 '평가 완료'로 간주하고 실행을 건너뛴(Skip) 캐시 히트 메커니즘 때문이었습니다.
* **바로잡은 사항:** 이미지가 없는 텍스트 전용 태스크에서는 절대로 `--vision-model` 옵션을 넣지 않도록 스크립트의 예외 처리 로직(`VISION_ARGS=""`)을 복구했습니다.
* **앞으로 유의할점:** 1) VLM 모델이더라도 이미지가 없는 텍스트 벤치마크를 돌릴 때는 `--vision-model` 옵션을 빼야 에러가 안 납니다. (해당 파라미터는 아키텍처 로드 옵션이 아니라 '이미지 입력 대기' 옵션에 가깝습니다.) 2) 벤치마크가 예상과 다르게 실행되지 않거나 개수가 적다면, 모델 에러를 의심하기 전에 **출력 폴더에 과거 파케이(Parquet) 파일이 남아있어서 프레임워크가 캐시 처리해 버린 것은 아닌지** 먼저 확인해야 합니다.
